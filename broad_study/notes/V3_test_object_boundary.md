# V3 测试对象与本人技术执行边界

本次复核对既有“本人开发/本人使用”和“主题对象另列”的规则作应用说明，未改冻结目录、主职能或来源。直接测试某对象，不自动证明本人开发该对象。例如测试 C++ SDK 不能单凭 SDK 的语言判定本人使用 C++ 编程。

工具/语言若只是被测产物的实现说明，且未明确被当作工具使用，记为 SEPARATE / TEST_OBJECT，保留原文及技术出现。直接运行软件/中间件测试或验证通信链路，可以支持该软件/协议的使用；不要求必须本人开发其实现。单凭“SDK（C++/Python）”则只知道SDK的语言接口，不能证明本人以该语言编程。测试方法、评测工具、测试系统的开发与使用按本人动作分别记录。

技术概念不可套用上述工具规则：冻结目录同时包含方法、问题、系统对象和质量目标。本人直接执行对电机、控制、导航等对象的技术测试，是围绕该概念的本人技术执行，使用口径保留，但不能解释为算法/电机开发。TC_RELIABILITY和TC_SAFETY本来包含明确系统可靠性、寿命、故障及安全目标，不要求额外出现专有技术方法。本人测试和设计工作中明确承担这些目标可计入；仅采购、协助、管理他人、下游应用背景仍另列。前几批过度收紧的条目以FOLLOWUP逐条纠正，旧记录保留可追溯。

这不是证据不存在，也不是目录外信息。最终两层分析的技术出现表必须纳入这些有语境的出现，并单列 TEST_OBJECT；职责执行表保持较窄口径。不能把 SEPARATE 从所有技术出现中消失，也不能把工作对象的出现比例说成技术使用比例。

收口时专项复查测试岗位中的技术概念、协议和工具，按各自测量类型而非相同关键词处理。对原文不足以区分对象/本人执行的条目保留未知，并报告边界敏感性。不得将整个职责使用指标都写成“使用了这些工具”。
