# 具身智能企业如何组织工作、表达技术资格？

[English](README.en.md) · [详细研究说明](docs/研究内容与主要发现.md) · [方法与数据指南](docs/METHODS_AND_DATA.md) · [复算指南](docs/REPRODUCTION.md) · [发布范围与版本](docs/PUBLICATION_SCOPE.md)

本项目研究具身智能企业的公开招聘广告，回答两个相互连接的问题：**企业通过哪些岗位与工作活动组织研发、工程和交付？当广告出现某项技术时，它究竟是在描述工作，还是在提出候选人的资格要求？**

研究以 **24 个招聘主体的 1,654 条广告**为基础。第一部分覆盖企业的职能构成、跨职能活动、工作对象和公司差异；第二部分在 **248 条广告、496 个广告—技术配对记录**上，检验技术提及、资格语境与无条件技术资格之间的区别。结果表明，岗位构成会改变公司比较，资格的定义也会改变技术排序。

这是**转向申请表研究之前的 V4.0 公开研究包**。本仓库同时发布原始招聘研究、英文论文及补充材料、源文本、编码规则、分析代码、结果表和研究记录。V1—V3 的英文稿与原交付包保存在历史目录中，便于追溯研究如何发展到 V4。

## 研究使用了什么数据

语料分两批采集：2026 年 8 月 31 日的 8 家企业、610 条广告，以及 9 月 11 日新增的 16 个主体、1,044 条广告。来源是企业的公开招聘页面，包括公开招聘系统与可阅读的岗位详情。每条记录保留招聘主体、来源岗位 ID、广告文本及文本版本哈希。

24 个主体中，23 个为整公司招聘范围，共 1,630 条广告；Amazon FAR 是单独列示的研究团队，共 24 条。全语料的主职能结构保留全部 1,654 条记录，其中 **1,576 条**进入 17 个具体职能的资格目录分析。V4 的三个任务层分别包含机器人学习／模型开发 105 条、机器人相关软件 87 条、板级电路 56 条广告。

## 用了什么方法

1. **按主要交付划分职能，再记录跨职能活动。** 一条广告具有一个主职能，但可以承担研究、工程、质量等多种活动。这样可以同时观察“招什么岗位”和“岗位实际做什么”。
2. **按职责证据确定任务与工作对象。** 任务归属依据工作内容，随后比较该任务中的技术表达。软件、模型、基础设施和机器人本体之间的联系通过原文记录。
3. **保存技术表达的语境和关系。** 资格目录包含 354 个条目与 22 个语境格，区分本人使用、本人开发、参与协作、一般要求、明确必备、优先条件，以及任选、示例、条件等语言关系。
4. **在同一广告中配对技术。** V4 比较 Python—PyTorch、C++—Linux、Altium—EMC/SI/PI，并将证据分为技术提及 M、资格语境出现 H、无条件技术特指资格 Q。另比较计入示例、计入任选时的排序。
5. **检查比较由什么驱动。** 采用职能构成分解、共同提及子样本、公司等权、完全相同文本与局部模板权重、逐一剔除公司、未知状态界限和 128 种已记录的语义读法。PyTorch—TensorFlow 同类技术扩展进一步检验语言关系的作用。

源文本判读采用模型辅助阅读与裁决；确定性 Python 程序构造统计量，并通过独立实现、SQL 去重及文件哈希核验计算。仓库公开编码证据和修订事务，读者可以从结果回查到原句。

## 得到了什么结论

### 1. 职能名称不能完整描述企业的工作分工

研究活动正例的 **48/66（72.7%）**位于“研究科学”以外的主职能；宽口径质量活动的 **300/459（65.4%）**位于“制造、质量与供应链”以外。研发和质量任务分布在多类岗位中，反映了跨职能工作组织。

### 2. 公司整体差异可以主要来自岗位构成

在 Galbot 与 Figure 的四个共同职能中，Galbot 的工程活动占比高 **11.10 个百分点**。分解得到，职能构成贡献 **+19.45 点**，职能内部贡献 **−8.35 点**；将四个职能等权后，差值变为 **−9.16 点**。公司总体比例与同职能比较会给出不同方向。

### 3. 计数规则会改变“哪项技术更受要求”的答案

在同一批 105 条机器人学习广告中：

|计数规则|Python|PyTorch|Python−PyTorch|
|---|---:|---:|---:|
|广告中的技术提及 M|73|83|−9.5 个百分点|
|一般／必备资格语境出现 H|67|79|−11.4 个百分点|
|无条件技术特指资格 Q|42|22|+19.0 个百分点|
|Q 加入全部已记录的示例关系|43|65|−21.0 个百分点|
|Q 加入任选及全部已记录的示例关系|50|75|−23.8 个百分点|

PyTorch 更常被提到；Python 更常被无条件、单独地写成资格；把框架示例计入以后，PyTorch 再次领先。**“熟悉框架，如 PyTorch”与“熟悉 PyTorch”表达了不同的资格关系。**

### 4. 这种差异在同一广告内仍然存在

66 条广告同时提到 Python 与 PyTorch。两者进入资格语境的数量接近（60 对 62），但无条件资格为 37 对 18。加入示例后成为 38 对 51；此时已记录未知状态允许的差值范围跨过零。排序取决于所研究的资格关系。

### 5. 不同技术组合表现出不同变化

机器人软件中，C++ 的提及数为 80/87，Linux 为 52/87；无条件资格的确认正例则为 38 与 47。在 48 条共同提及广告中，分别为 26 与 44。板级电路中，Altium 与 EMC/SI/PI 的提及数为 24 与 36，资格语境出现为 21 与 20，无条件资格为 5 与 15。工具、语言、操作环境与工程方法的表达方式有差异。

### 6. 同类技术对照帮助定位排序变化的来源

在 105 条机器人学习广告中，PyTorch 被提及 83 次、TensorFlow 26 次。26 条共同提及广告内，两者的资格关系确认正例数在各计数规则下相同。这个对照提示，解释 Python—PyTorch 的排序变化时，应考虑技术类别及其常用表达方式。

这些发现为招聘广告研究提供了具体方法：**先确定工作与比较对象，再明确“资格”包含哪些关系，同时报告公司构成与文本权重如何影响结果。** 对招聘者而言，明示必备、可替代工具和示例框架，也能让申请人更准确地理解准入条件。

## 如何复算

Python 3.12 或更高版本即可复算 V4 的数值分析：

```bash
git clone https://github.com/Okaren1106/embodied-ai-hiring-v4.git
cd embodied-ai-hiring-v4
python tools/reproduce.py v4
```

全样本研究的大表采用 gzip 无损压缩；恢复后可读取全部状态与结果。运行全样本复算需要数 GB 可用空间：

```bash
python tools/restore_large_files.py
python tools/reproduce.py broad
```

详细顺序、依赖、文件校验与可选独立核验见[复算指南](docs/REPRODUCTION.md)。[PUBLICATION_MANIFEST.json](PUBLICATION_MANIFEST.json)记录公开文件的 SHA-256；[SOURCE_PROVENANCE.json](SOURCE_PROVENANCE.json)记录对应原始交付文件；[COMPRESSION_MANIFEST.json](COMPRESSION_MANIFEST.json)记录压缩前的大小与哈希。

## 解释范围

本研究描述所采集企业的广告与资格表达。广告是公开劳动需求的文本证据，观测单位是广告；样本为目的性选择的两个横截面。语义编码尚无独立人工双编码信度，未知赋值范围表示已记录歧义的影响。原研究已撤回口径不一致的部署活动结论，撤回记录随数据一并保留。论文原稿和旧版本按历史状态发布，最新技术配对结果以 V4 为准。
