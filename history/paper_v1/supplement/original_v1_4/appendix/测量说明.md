# 测量说明

本说明适用于论文v1.2至v1.4所用的既有统计口径。活动继承measurement-v0.7.4，v0.7.5中本次使用的活动定义相同；技术结果采用`Astra-Q2-v2.1-review3`及`run_20260917_astra_core_q2_v3`的最终状态。以下说明不重新划分样本或重编码。规则原件及计算程序保存在[rules](rules/)，来源与哈希见[revision_source_manifest.json](revision_source_manifest.json)。

## 1 活动及承担关系

| 活动 | 正例所需内容 | 不自动计入的近似表达 |
| --- | --- | --- |
| 研究探索 ACT_RESEARCH | 具体研究问题或对象，并有方法探索或科学检验 | 单纯复现、调参、性能优化、极限性能或创新口号 |
| 工程 ACT_ENGINEERING | 工程实现、集成、调试与可运行系统交付 | 仅凭工程岗位名称、实际制造装配或采购供应执行，不能自动推定 |
| 宽质量 ACT_QUALITY | 验证执行、质量放行、合规或缺陷闭环 | 仅在资格中说有质量工作经验，不自动证明本岗位将执行该活动 |

三项可以同时成立，但每项需要相应职责证据。制造执行另有ACT_MANUFACTURING，不由主职能推定工程或质量；制造质量供应链主职能内的工程活动率因此不必接近100%。

本文的活动分子只计OWNED：岗位直接承担，包括明确共同负责。PARTICIPATES表示参与、协助，不进入这里的活动分子。84条对象案例允许承担或参与，两项分析的承担口径不同。统计前先按关系筛选，再在广告—活动内去重。程序依据为[rules/common.py](rules/common.py)的OWN/PART集合及[rules/compute_astra_final.py](rules/compute_astra_final.py)的活动汇总。

已存边界例为智元N0440：“优化具身算法模型结构，以支持具身算法的实现和高效运行。”既有记录将该职责记为ACT_ENGINEERING、OWNED。这个句子本身没有充分建立研究探索；“优化”不自动等于“研究”。[原编码片段](activity_boundary_example.json)与S3中的完整广告保留原版本。此例解释既有规则，不对其他职责另作新判读。

## 2 要求方式与限定分支

| 维度 | 正面判据 | 范围处理 |
| --- | --- | --- |
| GENERAL | 普通任职条件中的熟悉、经验、能力等要求，未明确硬化为必须 | 使用GENERAL_REQUIREMENT与EXPERIENCE_REQUIREMENT记录；不能仅凭技术词或程度形容词判断 |
| REQUIRED | 明确必须、必备、required等要求 | Required Skills等明确标题形成章节默认；具体项目旁的局部修饰可覆盖默认 |
| PREFERRED | 优先、加分、preferred等 | 仅对其修饰的项目生效，不能扩散到同广告其他直接要求 |
| UNCONDITIONAL | 对应方式下直接项或合取项，祖先中没有任选、示例或未解限制 | 只指编码关系，不表示经济学上必需，也不表示不存在其他资格条件 |
| CHOICE | OR、OR_EQUIVALENT、SOME_OF等明确选择关系 | 对所支配选项生效，保留明确“至少一种”等含义 |
| EXAMPLE | EXAMPLE关系，如“例如”“如”“等”所列范围 | 仅示例不证明列举技术相互可替代 |
| CHOICE_AND_EXAMPLE | 技术项及祖先中同时存在选择与示例 | 两类限定同时保留 |
| UNRESOLVED | 任一影响该项的祖先关系尚未解明 | 优先保留未解；缺失节点不能自动当作无条件 |

章节和列表作用域需要读取全文，不能以`duties`或`requirements`字段名直接决定语境；原来源可能把两个章节合并在同一字段。冻结规则允许章节默认被具体技能旁的局部修饰覆盖。not optional、not mandatory、否定要求等亦须按其真实含义区别处理，不能只命中required一词。判据见[rules/Q_coding_rules_v2.json](rules/Q_coding_rules_v2.json)、[measurement-v0.7.4](rules/measurement_rules_v0.7.4.yaml)与[要求作用域沿革](rules/requirement_scope_history.md)；沿革文件的旧版标头不表示它取代最终规则。

程度与要求方式分开。Dexterity N0874的“Strong Python programming skills”位于Required Skills下，最终为REQUIRED—UNCONDITIONAL。Agility E0329的“Deep experience with Altium for component generation and schematic entry”位于About You及其资格说明下，为GENERAL—UNCONDITIONAL。后者Bonus Points中的另一组Altium片段保留各自优先及分支信息，不取消前面的正例。

帕西尼N0339在“任职资格—三、技能要求”下写“熟悉至少一种EDA工具（如Altium Designer、PADS等）进行原理图绘制和PCB布局设计”，对应GENERAL—CHOICE_AND_EXAMPLE；同一广告职责中的EDA列举另行保存。智元N0440的“熟悉PyTorch、JAX、TensorFlow等深度学习框架”最终只记GENERAL—EXAMPLE。其历史理由曾把任选与示例并列，后续`review_reason`已明确“等为示例，原文没有任选”；展示以最终记录为准，历史理由仍保留。

## 3 广告级状态与分母

同一广告、同一技术、同一要求方式与分支独立归并。最终G程序的优先次序是：存在该格明确正例则P；否则依次检查该格来源限制SOURCE_EXCLUDED、不适用理由NA、影响该格的未解证据U；均不成立才为Z。局部未知不得污染不受影响的其他格，另处已明确的同格正例也不因一个未解片段而消失。见[rules/materialize_astra_final.py](rules/materialize_astra_final.py)的`resolve`。

P表示至少一处明确正例。Z表示既有阅读与适用范围内未记录该格正例，不是重新验证过的“绝无此要求”。U表示影响该项语境的未解对象、责任或分支。未执行PENDING不能写成Z或U。M另按本人职责或资格中的可辨识提及归并；示例和未解关系中仍可能有明确技术提及，M不能借用G的状态。W按广告分别计职责、必备、一般与优先，可重叠。

点值为P/N，其中N=P+Z。已识别未知的赋值界限为P/B至(P+U)/B，其中B=N+U；NA与SOURCE_EXCLUDED另列。N=0时点值缺失，B>0时仍可列未知界限。界限不包含尚未发现的语义错误，也不是置信区间。

## 5 EMC/SI/PI家族指标

V2_EMC_SIPI的目录定义为明确的电磁兼容、抗扰、信号或电源完整性分析与设计。目录别名包括EMC、EMI、SI/PI、signal integrity、power integrity；最终证据还将相应设计语境中的隔离、接地、ESD、浪涌、屏蔽和滤波归入该家族。它不是对这些词的无条件关键词并集，采购符合标准器件或一般高速PCB设计不足以证明本人承担该类分析或设计。目录原件见[rules/Q_catalog_v2_frozen.json](rules/Q_catalog_v2_frozen.json)。

成员先按相应语境判定，再对广告取并集。多个成员不能累加成多条广告。对家族指标而言，在家族内部任选成员可以仍明确要求这一家族中的能力；不能反推每个成员都被要求。当备选项还包括家族外内容或分支未解时，不能用这个规则强行合并为无条件。

例如N0466的“了解隔离、接地、ESD、浪涌、EMC、信号完整性或电源完整性设计”位于优先范围，最终为PREFERRED—UNCONDITIONAL：列举内容处于同一冻结家族，句中的“或”不要求所有成员同时成立。该状态也不是GENERAL正例。相反，E0166涉及“高速信号或解串器”的PCB设计片段保留为SEPARATE/CIRCUIT_DESIGN_OBJECT，没有因词面相近自动计入家族正例。各项原文与理由均在S3。

因此Altium的特定软件名称与EMC/SI/PI家族具有不同粒度。正文比较的是这两个具体指标的表达位置，不据其比例推导全部软件工具与工程方法的普遍差别。

## 6 证据导出的含义

S3保留短片段、完整原文行及所在字段的全部内容，并列同广告同技术的全部保留证据。最近标题与其他标题候选是定位辅助，跨行作用域应结合完整字段和历史要求组读取。历史树与旧理由用于追溯，不能覆盖后续最终metric、branch及review_reason。导出验证检查身份、版本、文字位置和状态连接，不新增语义标签，不估计准确率。
