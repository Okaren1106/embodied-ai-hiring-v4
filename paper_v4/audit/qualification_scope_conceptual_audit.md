# Qualification scope: independent review

The wider measure materially changes the empirical conclusion and should be part of the main analysis. In robot-model advertisements, Python is less common than PyTorch both as any mention (73 versus 83 of 105) and within recorded general/required qualification scope (67 versus 79). Python is more common only under the narrower rule that excludes local alternatives, examples and unresolved operators: current Q has 42 versus 22 confirmed positives after all seven source corrections.

Allowing EXAMPLE qualification branches produces 43 versus 65 positives and an unknown-assignment difference range of −24.76 to −4.76 percentage points. In the 66 advertisements mentioning both names, the corresponding numbers are 38 versus 51, with a range of −24.24 to +3.03 points. These v4 values include all three existing v3 example clarifications plus the adopted N0508 propagation correction; earlier exploratory values are superseded.

This supports a question about **the specificity of advertised qualifications**, not the claim that Python is more often a qualification in the broad sense. A category-level requirement can be explicit even when one named member is an example or acceptable alternative. Statements such as “deep learning frameworks such as PyTorch” are qualifications; Q deliberately measures a narrower target-specific expression. “Direct qualification” alone can conceal that restriction and should always be operationally qualified.

## Implementation check

The independent verifier starts from v4 derived Q states, both source-correction ledgers and frozen context evidence, not production scope functions. It checks 456 exact quotation spans and field hashes and reaggregates all 496 target rows and 30 contrast rows. All 3,608 checks passed.

H equals the existence of an occurrence with recorded metric GENERAL or REQUIRED, regardless of branch. This matches `context_index.metrics_json` in the production check. It is an inherited scope measure, not a new semantic validation. GENERAL/REQUIRED occurrences with UNRESOLVED local operators are legitimately included when scope is treated as known. All currently unresolved Q rows have a recorded qualification-scope occurrence; H does not thereby resolve their target-specific operator.

`Q_plus_example` unions current Q positives with EXAMPLE qualification occurrences. `Q_plus_choice_example` additionally includes CHOICE and CHOICE_AND_EXAMPLE. No duty-only, preference-only or separate-object occurrence enters through these joins. The three v3-adjudicated example rows have the following exact correction mapping; immutable identities must determine the joins:

- A032 → E0057;
- A065 → N0158;
- A099 → N0486.

Their old context-evidence branch remains UNRESOLVED for provenance, but the existing adjudication must carry forward into these new constructs. The production script correctly adds their example status without rewriting old evidence. All three have current Q=Z and H=1; all enter the expanded measures as P. The v4 ledger adds EXAMPLE for N0508/PyTorch and E0071/C++, and CHOICE for N0634/C++, E0549/C++ and E0560/C++. All five likewise have current Q=Z and H=1; only the two EXAMPLE cases enter the example-only expansion, while all five enter the choice/example expansion.

The subsequent bounded parenthetical review adds V4_006/N0798 and V4_007/N1044, both with current Q=U and the named relation set {UNCONDITIONAL, EXAMPLE}. Each is P in both broader expansions because either allowed reading is included by those constructs. Their explicit-example and explicit-choice/example flags remain zero; an ambiguity flag distinguishes them. These are **two current U-to-P transitions** for each expanded construct. The named two-reading set is bounded, not an exhaustive theory of reader interpretations. A cue-only expansion should preserve U, while a jointly varied unconditional/example reading can diagnose the narrower scope question.

## What remains conditional

H is complete only relative to the captured, coded evidence and current source-scope rules. Its zero means no recorded GENERAL/REQUIRED target occurrence in that frame, not verified absence of a real employer qualification. PREFERRED qualification text is excluded, consistently with the comparison to current Q; do not call H “all candidate qualifications” unless that exclusion is stated. It is the **general-or-required qualification-context mention** measure.

The example expansions change the construct. They are not estimates of a latent true Q, and their ranges are not directly the same estimand as the current-Q ranges. Presenting the values together exposes the substantive consequence of a measurement definition; it must not be described as a conventional robustness test that Q failed.

The 24 source-reviewed discordances were selected under phase-four codes. Current v4 has 23 resolved discordances (22 forward, one reverse); N0798 is now Z/U. The correspondence of those patterns with Q is partly mechanical because the operators determine Q. They are useful source illustrations and a construct audit, not an independent validation or an employer-behavior mechanism test. The Chinese 等-only cases should be distinguished from explicit English examples and explicit alternatives.

The strongest defensible result is that technology names can be common in qualification scope while differing sharply in whether the name itself is expressed without a local choice/example qualifier. Technology category, linguistic conventions, writing style and the chosen coding rule jointly shape that pattern. No evidence here estimates employers' internal screening weights, worker skill stocks, relative hiring demand or substitution elasticities.
